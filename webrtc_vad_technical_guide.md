## 二、各頻帶機率值的取得方式

### 2.1 機率計算流程

```
對每個頻帶 (channel = 0 to 5):
    │
    ├─→ 對每個高斯 (k = 0, 1):
    │       │
    │       ├─→ 噪音機率 = GaussianProbability(feature, noise_mean, noise_std)
    │       │              × kNoiseDataWeights[gaussian]
    │       │
    │       └─→ 語音機率 = GaussianProbability(feature, speech_mean, speech_std)
    │                      × kSpeechDataWeights[gaussian]
    │
    ├─→ h0_test = Σ(噪音機率)  // 該頻帶的總噪音機率
    ├─→ h1_test = Σ(語音機率)  // 該頻帶的總語音機率
    │
    └─→ LLR[channel] = log₂(h1_test) - log₂(h0_test)
                     ≈ shifts_h0 - shifts_h1
```

### 2.2 高斯機率計算公式

在 `vad_gmm.c` 中實現：

```
P(x|μ,σ) = (1/σ) × exp(-(x-μ)² / (2σ²))
```

定點數格式：
- 輸入特徵 x: Q4
- 均值 μ: Q7
- 標準差 σ: Q7
- 輸出機率: Q20
- 加權後機率: Q27

### 2.3 修改程式碼以輸出機率

在 `vad_core.c` 的 `GmmProbability` 函數中添加輸出參數：

```c
// 在 vad_core.h 中定義輸出結構
typedef struct {
    int32_t noise_prob[6];      // 各頻帶噪音機率 (Q27)
    int32_t speech_prob[6];     // 各頻帶語音機率 (Q27)
    int16_t llr[6];             // 各頻帶對數似然比
    int32_t sum_llr;            // 加權總和
    int16_t vadflag;            // VAD 結果
} VadDebugInfo;

// 在 GmmProbability 迴圈中輸出
for (channel = 0; channel < kNumChannels; channel++) {
    // ... 現有計算 ...

    // 輸出機率值
    debug_info->noise_prob[channel] = h0_test;
    debug_info->speech_prob[channel] = h1_test;
    debug_info->llr[channel] = log_likelihood_ratio;
}
debug_info->sum_llr = sum_log_likelihood_ratios;
debug_info->vadflag = vadflag;
```

### 2.4 機率值轉換

```c
// Q27 轉換為浮點機率 (0.0 ~ 1.0 範圍外也可能)
double noise_prob_float = (double)h0_test / (double)(1 << 27);
double speech_prob_float = (double)h1_test / (double)(1 << 27);

// 計算實際的 log likelihood ratio
double actual_llr = log2(speech_prob_float / noise_prob_float);

// 或直接使用整數 LLR
// llr > 0 → 偏向語音
// llr < 0 → 偏向噪音
// llr = 0 → 不確定
```

## 三、GMM 模型更新機制

### 3.1 更新條件總覽

| 參數 | 更新條件 | 更新速率常數 | 說明 |
|------|----------|--------------|------|
| `noise_means` | vadflag = 0 | kNoiseUpdateConst = 655 (≈0.02) | 只在非語音時更新 |
| `noise_stds` | vadflag = 0 | 約 1/64 | 只在非語音時更新 |
| `speech_means` | vadflag = 1 | kSpeechUpdateConst = 6554 (≈0.2) | 只在語音時更新 |
| `speech_stds` | vadflag = 1 | 約 0.025 | 只在語音時更新 |

### 3.2 噪音模型更新 (vadflag = 0)

```c
// 位置: vad_core.c:299-325

// Step 1: 計算更新增量
delt = (ngprvec[gaussian] * deltaN[gaussian]) >> 11;

// Step 2: 更新均值 (短期)
nmk2 = nmk + (delt * kNoiseUpdateConst) >> 22;

// Step 3: 長期背景修正 (使用 100 幀內的最小值)
feature_minimum = WebRtcVad_FindMinimum(self, features[channel], channel);
ndelt = (feature_minimum << 4) - tmp1_s16;
nmk3 = nmk2 + (ndelt * kBackEta) >> 9;

// Step 4: 限制範圍
if (nmk3 < tmp_s16) nmk3 = tmp_s16;      // 下限
if (nmk3 > tmp_s16) nmk3 = tmp_s16;      // 上限
self->noise_means[gaussian] = nmk3;
```

### 3.3 語音模型更新 (vadflag = 1)

```c
// 位置: vad_core.c:327-378

// Step 1: 計算更新增量
delt = (sgprvec[gaussian] * deltaS[gaussian]) >> 11;
tmp_s16 = (delt * kSpeechUpdateConst) >> 21;

// Step 2: 更新均值
smk2 = smk + ((tmp_s16 + 1) >> 1);

// Step 3: 限制範圍
if (smk2 < kMinimumMean[k]) smk2 = kMinimumMean[k];
if (smk2 > maxmu) smk2 = maxmu;
self->speech_means[gaussian] = smk2;

// Step 4: 更新方差
ssk += (tmp_s16 >> 8);
if (ssk < kMinStd) ssk = kMinStd;
self->speech_stds[gaussian] = ssk;
```

### 3.4 模型分離機制

當語音模型和噪音模型太接近時，系統會自動將它們分開：

```c
// 位置: vad_core.c:411-445

// 計算兩個模型的全局均值差
diff = (speech_global_mean >> 9) - (noise_global_mean >> 9);

// 如果差距小於最小值，強制分離
if (diff < kMinimumDifference[channel]) {
    tmp_s16 = kMinimumDifference[channel] - diff;

    // 語音模型往上推 (~80%)
    tmp1_s16 = (13 * tmp_s16) >> 2;
    speech_global_mean = WeightedAverage(&self->speech_means[channel],
                                         tmp1_s16, ...);

    // 噪音模型往下推 (~20%)
    tmp2_s16 = (3 * tmp_s16) >> 2;
    noise_global_mean = WeightedAverage(&self->noise_means[channel],
                                        -tmp2_s16, ...);
}
```

## 五、VAD 效果調整策略

### 5.1 問題：語音漏檢 (False Negative)

**症狀**：說話時 VAD 經常返回 0

```c
// 方案 A: 降低閾值
static const int16_t kLocalThresholdQ[3] = { 18, 15, 18 };   // 原: 24, 21, 24
static const int16_t kGlobalThresholdQ[3] = { 40, 35, 40 };  // 原: 57, 48, 57

// 方案 B: 增加滯後時間
static const int16_t kOverHangMax1Q[3] = { 15, 8, 6 };   // 原: 8, 4, 3
static const int16_t kOverHangMax2Q[3] = { 25, 12, 9 };  // 原: 14, 7, 5

// 方案 C: 加快語音模型適應
static const int16_t kSpeechUpdateConst = 10000;  // 原: 6554
```

### 5.2 問題：噪音誤檢 (False Positive)

**症狀**：沒說話時 VAD 經常返回 1

```c
// 方案 A: 提高閾值
static const int16_t kLocalThresholdQ[3] = { 50, 45, 50 }; // ↑ 更難判為語音
static const int16_t kGlobalThresholdQ[3] = { 200, 150, 200 }; // ↑ 需要更高 LLR

// 方案 B: 加快噪音模型適應
static const int16_t kNoiseUpdateConst = 1500;  // 原: 655

// 方案 C: 減少滯後時間
static const int16_t kOverHangMax1Q[3] = { 4, 2, 2 };

```

### 5.3 問題：環境噪音變化大


## 六、長期使用的穩定性分析

### 6.1 問題：寬鬆閾值 + 持續更新 Speech GMM 的影響

**問題描述**：如果閾值設得很寬鬆，讓 VAD 幾乎一直返回 1（語音），同時持續更新語音 GMM，長期效果會如何？

### 6.2 理論分析

#### 會發生的問題

```
初始狀態:
┌─────────────────────────────────────────────────────────────┐
│                    Energy (dB)                              │
│  ▲                                                          │
│  │    Noise Model          Speech Model                     │
│  │    ┌──────┐              ┌──────┐                        │
│  │    │      │              │      │                        │
│  │   ╱│      │╲            ╱│      │╲                       │
│  │  ╱ │      │ ╲          ╱ │      │ ╲                      │
│  └──────────────────────────────────────────────────────→   │
│     低能量              高能量                               │
│         ↑                  ↑                                 │
│     噪音區域           語音區域                              │
└─────────────────────────────────────────────────────────────┘

長期寬鬆 VAD=1 後:
┌─────────────────────────────────────────────────────────────┐
│                    Energy (dB)                              │
│  ▲                                                          │
│  │    Noise Model     Speech Model (已漂移)                 │
│  │    ┌──────┐        ┌──────┐                              │
│  │    │      │        │      │                              │
│  │   ╱│      │╲      ╱│      │╲                             │
│  │  ╱ │      │ ╲    ╱ │      │ ╲                            │
│  └──────────────────────────────────────────────────────→   │
│     低能量     ↑   高能量                                    │
│                │                                             │
│         模型重疊，區分度下降                                  │
└─────────────────────────────────────────────────────────────┘
```

#### 退化過程

1. **語音模型均值漂移**
   - 噪音樣本被錯誤地用於更新語音模型
   - 語音模型的均值會逐漸向噪音特徵靠攏

2. **語音模型方差增大**
   - 混入噪音樣本導致分佈變寬
   - 模型變得更"模糊"

3. **區分能力下降**
   - 語音和噪音模型越來越相似
   - LLR 趨近於 0，判斷變得不確定

### 6.3 內建的保護機制

WebRTC VAD 有以下保護機制來減緩退化：

#### 機制 1: 模型分離強制 (vad_core.c:411-445)

```c
// 當兩個模型太接近時，強制分離
if (diff < kMinimumDifference[channel]) {
    // 語音模型往上推 80%
    // 噪音模型往下推 20%
}
```

**效果**：即使語音模型漂移，也會被強制與噪音模型保持一定距離。

#### 機制 2: 均值範圍限制

```c
// 語音模型上限
if (smk2 > maxmu) smk2 = maxmu;

// 語音模型下限
if (smk2 < kMinimumMean[k]) smk2 = kMinimumMean[k];
```

**效果**：語音模型均值不會無限制地漂移。

#### 機制 3: 標準差下限

```c
if (ssk < kMinStd) ssk = kMinStd;
```

**效果**：防止模型變得過於狹窄或崩塌。

### 6.4 長期影響評估

| 時間 | 影響程度 | 說明 |
|------|----------|------|
| 短期 (數秒) | 低 | 更新速率較慢，變化不明顯 |
| 中期 (數分鐘) | 中 | 語音模型開始漂移，但仍受保護機制限制 |
| 長期 (數小時) | 中高 | 模型達到保護機制的邊界，效果明顯下降 |

### 6.5 最終結論

**會退化，但有上限**：

1. ✅ 保護機制會限制最壞情況
2. ⚠️ 區分能力會下降，但不會完全失效
3. ⚠️ 噪音模型因為不更新 (vadflag=1 時)，會變得過時
4. ❌ 如果噪音環境變化，噪音模型無法適應

### 6.6 建議的解決方案

#### 方案 A: 定期重置模型

```c
// 每 N 幀強制重置為初始值
if (self->frame_counter % RESET_INTERVAL == 0) {
    for (int i = 0; i < kTableSize; i++) {
        self->speech_means[i] = kSpeechDataMeans[i];
        self->speech_stds[i] = kSpeechDataStds[i];
    }
}
```

#### 方案 B: 有條件地更新

```c
// 只在高置信度時更新語音模型
if (vadflag && sum_log_likelihood_ratios > HIGH_CONFIDENCE_THRESHOLD) {
    // 更新語音模型
}
```

#### 方案 C: 雙重驗證

```c
// 同時檢查能量和 LLR
if (vadflag && total_power > ENERGY_THRESHOLD &&
    sum_log_likelihood_ratios > LLR_THRESHOLD) {
    // 更新語音模型
}
```

#### 方案 D: 凍結語音模型

```c
// 如果不需要適應不同說話者，可以完全不更新語音模型
// 將 kSpeechUpdateConst 設為 0
static const int16_t kSpeechUpdateConst = 0;
```

## 七、GMM vs 簡單能量閾值比較分析

### 7.1 GMM 使用的特徵

**是的，GMM 使用的是能量特徵**，但有重要的差異：

```
GMM 特徵計算:
┌─────────────────────────────────────────────────────────────┐
│  輸入音訊                                                    │
│     │                                                        │
│     ▼                                                        │
│  ┌─────────────────────────────────────────────────────┐    │
│  │ 濾波器組分割成 6 個頻帶                               │    │
│  │ (80-250, 250-500, 500-1K, 1K-2K, 2K-3K, 3K-4K Hz)    │    │
│  └─────────────────────────────────────────────────────┘    │
│     │                                                        │
│     ▼                                                        │
│  ┌─────────────────────────────────────────────────────┐    │
│  │ 對每個頻帶計算: feature = 10 × log₁₀(energy)         │    │
│  │ 輸出: 6 維特徵向量 [f₀, f₁, f₂, f₃, f₄, f₅]          │    │
│  └─────────────────────────────────────────────────────┘    │
│     │                                                        │
│     ▼                                                        │
│  ┌─────────────────────────────────────────────────────┐    │
│  │ GMM 機率計算:                                         │    │
│  │ P(speech) = Π P(fᵢ | speech_model)                   │    │
│  │ P(noise)  = Π P(fᵢ | noise_model)                    │    │
│  └─────────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────┘

簡單能量閾值:
┌─────────────────────────────────────────────────────────────┐
│  輸入音訊                                                    │
│     │                                                        │
│     ▼                                                        │
│  ┌─────────────────────────────────────────────────────┐    │
│  │ 計算總能量: E = Σ x[n]²                              │    │
│  └─────────────────────────────────────────────────────┘    │
│     │                                                        │
│     ▼                                                        │
│  ┌─────────────────────────────────────────────────────┐    │
│  │ 比較閾值: if (E > threshold) → 語音                   │    │
│  └─────────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────┘
```

### 7.2 關鍵差異比較

| 特性 | WebRTC VAD (GMM) | 簡單能量閾值 |
|------|------------------|--------------|
| **特徵維度** | 6 維 (各頻帶能量) | 1 維 (總能量) |
| **頻譜資訊** | ✅ 保留頻譜分佈 | ❌ 只有總能量 |
| **決策方式** | 機率模型 (LLR) | 硬閾值比較 |
| **適應性** | ✅ 模型自動更新 | ❌ 閾值固定 (或需手動) |
| **軟判決** | ✅ 可輸出置信度 | ❌ 只有 0/1 |
| **計算複雜度** | 中 | 低 |

### 7.3 為什麼頻譜分解很重要

#### 例子：風扇噪音 vs 人聲

```
風扇噪音頻譜:          人聲頻譜:
│ ▓▓▓▓                │
│ ▓▓▓▓                │     ▓▓▓▓
│ ▓▓▓▓                │     ▓▓▓▓▓▓▓▓
│ ▓▓▓▓                │ ▓▓▓ ▓▓▓▓▓▓▓▓▓▓
│ ▓▓▓▓▓▓              │ ▓▓▓▓▓▓▓▓▓▓▓▓▓▓
└──────────────────   └──────────────────
  低頻 ←────→ 高頻       低頻 ←────→ 高頻

風扇: 能量集中在低頻
人聲: 能量分佈在多個頻帶，有諧波結構
```

**簡單能量閾值的問題**：
- 如果風扇噪音和人聲總能量相近，無法區分
- 只看總能量會誤判

**GMM 的優勢**：
- 可以學習「人聲在 250-500Hz 和 1K-2K Hz 通常有較高能量」
- 可以學習「風扇噪音主要在低頻」
- 透過頻譜分佈來區分

### 7.4 什麼情況下效果相近

如果你的應用場景符合以下條件，簡單能量閾值可能就足夠：

| 條件 | 說明 |
|------|------|
| ✅ 背景很安靜 | 噪音能量遠低於語音能量 |
| ✅ 噪音穩定 | 噪音特性不會變化 |
| ✅ 只需粗略判斷 | 不需要精確的語音邊界 |
| ✅ 語音很響亮 | SNR 很高 (> 20dB) |

### 7.5 GMM 真正的價值

```
場景: 中等噪音環境 (SNR ≈ 10-15 dB)

簡單能量閾值:
┌────────────────────────────────────────────────────────┐
│ 能量                                                    │
│  ▲       語音+噪音                                      │
│  │    ┌──────────────┐                                 │
│  │    │ ████████████ │  ← 有語音時的能量               │
│  │....│..............│........................閾值.....│
│  │    │ ░░░░░░░░░░░░ │  ← 純噪音時的能量               │
│  │    └──────────────┘                                 │
│  └──────────────────────────────────────────────→ 時間  │
│                                                         │
│  問題: 語音和噪音的能量可能重疊，閾值很難設定           │
└────────────────────────────────────────────────────────┘

GMM 方法:
┌────────────────────────────────────────────────────────┐
│ 即使總能量相近，頻譜分佈不同                            │
│                                                         │
│ 噪音: [高, 中, 低, 低, 低, 低]  ← 能量集中低頻          │
│ 語音: [中, 高, 高, 高, 中, 中]  ← 能量分佈較均勻        │
│                                                         │
│ GMM 可以學習這種模式差異                                │
└────────────────────────────────────────────────────────┘
```

### 7.6 實驗建議

如果你想驗證在你的場景下兩種方法的差異：

```python
import numpy as np

def simple_energy_vad(audio_frame, threshold):
    """簡單能量閾值 VAD"""
    energy = np.sum(audio_frame ** 2)
    return 1 if energy > threshold else 0

def subband_energy_vad(audio_frame, thresholds):
    """多頻帶能量閾值 (介於兩者之間的方法)"""
    # 用 FFT 分解成頻帶
    fft = np.fft.rfft(audio_frame)
    freqs = np.fft.rfftfreq(len(audio_frame), 1/8000)

    bands = [(80, 250), (250, 500), (500, 1000),
             (1000, 2000), (2000, 3000), (3000, 4000)]

    votes = 0
    for i, (low, high) in enumerate(bands):
        mask = (freqs >= low) & (freqs < high)
        band_energy = np.sum(np.abs(fft[mask]) ** 2)
        if band_energy > thresholds[i]:
            votes += 1

    return 1 if votes >= 3 else 0  # 多數投票
```

#### 為什麼 GMM 在低 SNR 更好

```
關鍵設計 1: 頻帶權重
┌────────────────────────────────────────────────────────────┐
│ kSpectrumWeight = { 6, 8, 10, 12, 14, 16 }                 │
│                    ↑                  ↑                    │
│                 低頻權重低         高頻權重高               │
│                                                            │
│ 原因: 噪音通常集中在低頻，語音的高頻諧波更有區分度          │
└────────────────────────────────────────────────────────────┘

關鍵設計 2: 自適應噪音模型
┌────────────────────────────────────────────────────────────┐
│ 噪音模型會持續追蹤環境變化                                  │
│                                                            │
│ 時間 →                                                     │
│ 噪音能量: ████████████████████████████████                 │
│                        ↑ 風扇轉速提高                       │
│ noise_mean:  ──────────╱─────────────── (自動上調)         │
│                                                            │
│ 結果: 即使噪音變大，GMM 仍能正確區分                        │
└────────────────────────────────────────────────────────────┘

關鍵設計 3: 機率決策 vs 硬閾值
┌────────────────────────────────────────────────────────────┐
│ GMM:    P(speech|features) vs P(noise|features)            │
│         → 軟決策，考慮所有頻帶的綜合證據                   │
│                                                            │
│ 閾值:   if (energy > threshold)                            │
│         → 硬決策，一刀切                                   │
│                                                            │
│ 邊界情況處理:                                               │
│ - GMM: 可以輸出置信度，讓應用層決定如何處理                │
│ - 閾值: 只有 0/1，沒有中間地帶                             │
└────────────────────────────────────────────────────────────┘
```

### 7.8 結論

| 問題 | 答案 |
|------|------|
| GMM 是用能量訓練的嗎？ | ✅ 是，用各頻帶的 log 能量 |
| 跟簡單能量閾值效果一樣嗎？ | ❌ 不一樣 |
| 差在哪裡？ | 頻譜分解 + 機率模型 + 自適應 |
| 什麼時候差不多？ | 高 SNR、安靜環境、穩定噪音 |
| 什麼時候 GMM 明顯更好？ | 低 SNR、複雜噪音、多變環境 |

**簡單總結**：
- **高 SNR (> 20dB)**：簡單能量閾值可能就夠用
- **中 SNR (10-20dB)**：GMM 的頻譜分解開始發揮作用
- **低 SNR (< 10dB)**：GMM 明顯更好，但也會開始失效

## 八、Frame Size 與 Hop Size 設定

### 8.1 支援的 Frame Size

WebRTC VAD 只支援特定的幀長度：

| 取樣率 | 10ms | 20ms | 30ms |
|--------|------|------|------|
| 8 kHz  | 80   | 160  | 240  |
| 16 kHz | 160  | 320  | 480  |
| 32 kHz | 320  | 640  | 960  |
| 48 kHz | 480  | 960  | 1440 |

**限制原因**：濾波器組係數是針對這些幀長預先計算的，使用其他長度會導致：
- 濾波器響應不正確
- 能量計算的 Q 格式錯誤
- GMM 模型匹配失效

### 8.2 Hop Size 調整

Hop size 可以自由調整，不受 VAD 內部限制：

```c
// 原始: hop_size = frame_size (無重疊)
for (int i = 0; i < total_samples; i += frame_size) {
    vad_result = WebRtcVad_Process(vad, fs, &audio[i], frame_size);
}

// 自訂 hop_size (例如 50% 重疊，更細緻的時間解析度)
int frame_size = 160;  // 10ms @ 16kHz
int hop_size = 80;     // 5ms
for (int i = 0; i + frame_size <= total_samples; i += hop_size) {
    vad_result = WebRtcVad_Process(vad, fs, &audio[i], frame_size);
}
```

### 8.3 非標準 Frame Size 的處理

如果系統使用非標準幀長（如 25ms），建議方案：

| 方案 | 做法 | 複雜度 |
|------|------|--------|
| 重採樣適配 | 將 25ms 音訊重採樣到 20ms 或 30ms | 低 |
| 累積緩衝 | 累積多幀後再送入 VAD | 中 |
| 修改原始碼 | 重新設計濾波器係數（不建議） | 高 |

```c
// 累積緩衝範例
static int16_t buffer[480];  // 30ms @ 16kHz
static int buffer_pos = 0;

void process_25ms_frame(int16_t* frame_25ms) {
    // 累積到緩衝區
    memcpy(&buffer[buffer_pos], frame_25ms, 400 * sizeof(int16_t));
    buffer_pos += 400;

    // 當累積夠 30ms (480 samples) 時處理
    if (buffer_pos >= 480) {
        WebRtcVad_Process(vad, 16000, buffer, 480);
        buffer_pos = 0;
    }
}
```
