NR C library(MMSE-LSA denoiser)— NR/c_impl

概要

AnrDenoiser(V3-2)是 OM-LSA 族降噪核心:Ephraim-Malah 1985 MMSE-LSA 增益 + Cohen&Berdugo 2002 MCRA 噪聲估計 + 2001 Bayesian SPP。頻域 I/O:輸入/輸出都是 Complex[n_freqs] 頻譜,window / forward FFT / inverse FFT / OLA 全由呼叫端負責(串在 AEC 之後時,NR 不另做 FFT,直接吃 AEC 已算好的頻譜:mono 範例吃 aec_get_residual() 檢視的 base_spec(守衛未觸發時就是 error_spec),4ch 是同一個檢視的 error_spec)。純 DSP、無 NN/NPU 成分;全部 state 收在 AnrDenoiser C struct(caller pool 或 heap)。

串在 AEC 之後的整合碼(Audio_ALG 的 pipelines/mono/aec_nr_res/main.c,每支範例 main 自己初始化 NR、自己寫一小段串接;單聲道的 mono_nr_gain()、4ch 的 array_sample_anr_gain()(pipelines/4ch/array_sample_post.h)都是呼叫端自己的薄包裝)使用的 seam 是 anr_process_gain_with_residual_psd()(沒有殘留回音 PSD 時用 anr_process_gain()):算出每 bin 增益但不套用、直接回傳內部增益陣列,並把外部殘留回音 PSD R² 折進噪聲底(ξ = S²/(N²+R²),R² 先乘 noise_over_subtraction 同一倍率);MCRA 追蹤器只吃乾淨功率,R² 不污染噪聲估計。AEC 的 R² 是 int16² 尺度,餵給 NR 前要乘 1/32768²。RES 增益:AecConfig.residual = AEC_RESIDUAL_FULL 時由 AEC 實例自己算(單聲道與 4ch 陣列實例都在 aec_process_residual();aec_process() 是線性、殘留兩級加合成的一次呼叫,沒有讓 NR 插入增益的位置),以 aec_get_residual() 檢視的 res_gain 取得。NR 的增益交給 aec_apply_gain(),由它取 min(G_nr, G_res) 並乘在渲染底座上,aec_apply_cng() 補被切掉的 bin;逐步呼叫與可編譯的骨架見 NR API §4.1。

延遲與 warm-up

  • 演算法延遲 = 0 樣本:頻域增益同 hop 產出;框架延遲(window+FFT / IFFT+OLA,50% overlap 下為 1 hop:16k/256 = 128 樣本 = 8 ms、16k/512 = 16 ms、48k/1024 = 10.667 ms)由呼叫端的 transform 負擔——mono 整合範例的端到端 1 hop 就來自這層(參見 aec.html 延遲表)。16k/256 的脈衝實測:輸出峰值比輸入晚 128 樣本。
  • Warm-up = num_init_frames(≈200 ms,格點重定時:16k/256=25 幀、16k/512=13 幀、48k=19 幀,實測):期間累積噪聲底、增益=1 直通(不抑制),第 num_init_frames 個非全零 hop 完成 noise_estimator_init_noise()、anr_is_initialized() 轉 true,但那一個 hop 的 gain 仍是 1,下一個 hop 才開始抑制。數位靜音 hop(所有 bin 恰為 0)不計入 warm-up、也不推進噪聲追蹤(實測 30 個全零 hop 後仍未初始化,gain 維持 1)。初始化之後的全零 hop 不會被強制為 gain=1,照常算 gain,只是不推進噪聲底追蹤器(實測 16k/256、40 個以上噪聲 hop 之後的全零 hop 平均 gain 約 0.2)。
  • MCRA 最小值追蹤窗 L(balanced 實測 64/32/48 幀 ≈ 512 ms)決定噪聲底適應新環境的時間尺度;場景偵測(上半頻帶 γ 超門檻且頻譜平坦度超門檻,連續 scene_change_min_frames 個 hop 才重置)提供快速路徑;broadband_threshold<1 時另有寬頻起音閘。
