NR C API 使用說明 — NR/c_impl

本頁是整合者視角的 API 說明：init/process 要呼叫什麼、input/output 怎麼給、錯誤與 reset 怎麼處理。演算法內部機制與逐層時序圖見 nr.html;外部／內部參數表與函式分級見 nr_c_api_params.html;完整欄位與錯誤語意的 canonical 出處是 NR/docs/c_user_manual_zh_TW.md。函式內部自行呼叫的子模組不在本頁範圍。

1. 責任邊界(先看這個)

NR 是純頻域 MMSE-LSA/OMLSA 降噪核心。它只吃 Complex[n_freqs]、只吐 Complex[n_freqs],不含 window、FFT、IFFT、OLA 或任何 PCM buffer 邏輯——這些全部是呼叫端的責任(NR/c_impl/include/anr.h)。

如果 application 手上只有 PCM,不要自己補一套 WOLA。照 Audio_ALG 的 串接範例 與 pipelines 下的範例 main 的做法(它們已經把 window/FFT/OLA/gain fusion 做對了)。

連結時需要兩個 archive:libanr.a 與 libaudio_common.a——NR 自己不含 FFT。

2. 這個 lib 可以設定的 grid(與 AEC 不同,注意)

anr_validate_config()(anr_types.h)接受五組 grid。硬性關係:frame_size == fft_size(不補零)、hop_size == frame_size/2(固定 50% overlap)。

sample_ratefft_size = frame_sizehop_sizehop 時長n_freqs呼叫端 WOLA 延遲（1 hop）狀態
8000128648.000 ms658.000 ms8k 預設
800025612816.000 ms12916.000 ms8k 替代
160002561288.000 ms1298.000 ms產品預設(低延遲)
1600051225616.000 ms25716.000 ms產品替代(高頻率解析度)
48000102451210.667 ms51310.667 ms48k 唯一 grid

NR 核心本身 0 延遲（同 hop 產出增益）；表中延遲來自呼叫端的 sqrt-Hann WOLA（50 % overlap 的 window+FFT／IFFT+OLA），實測 16k/256 的脈衝輸入到輸出差 128 樣本＝1 hop。

兩個產品 sample rate(16k／48k),而 16 kHz 是唯一有兩種 hop 可選的。選 hop 的取捨:

選 16k/256(hop 128)選 16k/512(hop 256)
延遲減半(8 ms vs 16 ms)頻率解析度加倍(129→257 bins),低頻噪聲與 tonal 成分分得更開
每秒處理次數加倍 → CPU 較高每秒處理次數減半 → CPU 較低
對瞬態/起音反應快長窗對非穩態噪聲反應較鈍
記憶體 45,344 B記憶體 56,432 B
與 AEC 的 grid 表不完全相同。AEC 不接受 8k/128(它的 8k legacy grid 是 256/128);NR 的 8 kHz 預設卻是 128/64(anr_default_fft_size(),anr_types.h)。串成一條鏈時不要各自呼叫各自的 default,要由上層 resolve 出同一組 (sample_rate, fft_size, hop) 再明確傳給兩邊。

建立後不可中途換 grid:anr_reconfigure() 連 grid 都不給換(anr.c),要換必須 destroy 重建。

3. 建立與生命週期

兩條路徑永遠同時編進同一份 object(不是 #ifdef 二選一);handle 內有 runtime flag is_static,destroy() 靠它決定要不要真的 free()(anr.c)。

A. Static pool(板端路徑)

#include <stdint.h>
#include "anr.h"

static uint8_t g_pool[48 * 1024] __attribute__((aligned(16)));   /* >= anr_get_mem_size(&cfg) */

AnrDenoiser *nr_create_static(void)
{
    AnrConfig cfg = anr_config_for_mode_grid(16000, 256, ANR_MODE_BALANCED);
    if (!anr_validate_config(&cfg)) return NULL;     /* 唯一能事先知道為何被拒的手段 */

    size_t need = anr_get_mem_size(&cfg);            /* 0 = config 無效或尺寸溢位 */
    if (need == 0 || need > sizeof g_pool) return NULL;

    return anr_init(g_pool, sizeof g_pool, &cfg);    /* NULL = 未對齊 / pool 太小 / config 無效 */
}

void nr_end_of_stream(AnrDenoiser *nr)
{
    /* ... 每 hop 呼叫 anr_process() 或 anr_process_gain() ... */
    anr_reset(nr);     /* 串流邊界:同時清呼叫端自己的 analysis / OLA buffer */
    anr_destroy(nr);   /* static 實例是真 no-op,可重複呼叫;pool 由呼叫端持有、呼叫端釋放 */
}

B. Heap(桌面/測試)

AnrConfig cfg = anr_config_for_mode(16000, ANR_MODE_BALANCED);
AnrDenoiser *nr = anr_create(&cfg);   /* NULL = config 無效或配置失敗 */
anr_destroy(nr);                      /* heap 實例只能呼叫一次,重複呼叫 = double free */

4. 每-frame 處理入口

入口什麼時候用
anr_process()NR 是最後一級:直接把 gain 套上頻譜(相位不變)
anr_process_gain()NR 是串接鏈的一環:只要 gain、不要套用,交給上層與 AEC/RES 的 gain 融合
/* A. 直接套用,可 in-place */
if (anr_process(nr, spectrum, spectrum) != 0) { /* self / 輸入 / 輸出為 NULL */ }

/* B. 只取 gain(串接鏈都走這條) */
float gain[257];                                 /* >= anr_get_n_freqs(nr) */
if (anr_process_gain(nr, error_spec, extra_noise_psd, gain) != 0) { /* self / error_spec 為 NULL */ }
/* gain_out 傳 NULL 時改讀 anr_get_gain(nr, NULL) */
項目契約
buffer 長度全部 n_freqs = fft_size/2+1;函式沒有長度參數,傳錯不會替你報錯
FFT 誰做呼叫端。NR 不碰時域
Aliasingspectrum_out == spectrum_in(完全同一指標)支援;完全不相交也支援;部分重疊不支援(anr.c)
extra_noise_psd長度 n_freqs,可為 NULL。非 NULL 時做 echo-as-extra-noise:ξ=S²/(N²+R²),只餵進 SPP／先驗 SNR；MCRA 噪聲估計仍只用輸入功率更新
gain_out可傳 NULL 省一次 memcpy,之後用 anr_get_gain() 讀同一份
回傳值0 成功;-1 表示必要的 self／spectrum_in(anr_process() 另含 spectrum_out)為 NULL,此時狀態未動。extra_noise_psd／gain_out 傳 NULL 是合法用法
初始化期前 num_init_frames 個非全零 frame 是 pass-through(gain 全 1.0),同時累積噪聲統計；第 num_init_frames 次呼叫完成初始化，但那一次的 gain 仍是 1.0，下一個 hop 才開始抑制。數位靜音 frame(所有 bin 功率恰為 0)不是錯誤、回 0：初始化前 gain=1 且不計入暖機；初始化後仍照常算 gain(不會被強制為 1，實測 16k/256 在 40 個以上噪聲 hop 之後的全零 hop 平均 gain 約 0.2)，只是不推進噪聲底追蹤器(anr.c frame_is_silent()、process_init_or_gain())
Aliasing 規則與 FFT 層相反。fft_forward()／fft_inverse() 用 restrict,任何重疊(含完全相同指標)都是 UB;NR 這裡卻明確支援完全同一指標。兩層不要套用同一條直覺。
接 AEC 的 r2 時要先換算尺度。AEC 的殘留回音 PSD(SeSpecFrame.r2／AecResContext.r2)是 int16² 尺度,而線性誤差頻譜 E 是 audio 尺度,直接當 extra_noise_psd 前必須除以 32768²。範例層的 se_anr_stage_gain()(pipelines/samples/se_anr_stage.h)已做這件事,且只在 frame->usable_linear 為真時才併入;application 不要自己另推一份。

5. 參數設定：用 mode，不要逐欄位手調

設定強度的正規做法是選一個 AnrMode。anr_config_for_mode_grid() 的四級只改 g_min_db、q、xi_min_db、noise_over_subtraction；DD、tracker、gain dynamics 與低頻語音 guard 的組態欄位共用。例外是幀級語音閘 speech_protect_frame_threshold:設定值著作於 balanced 的 q = 0.52,生效值為 value + (q − 0.52),隨 preset 位移(mild 0.61 / moderate 0.57 / balanced 0.55 / aggressive 0.48;可用 anr_get_speech_protect_frame_threshold() 讀回)。

AnrModeg_min_dbqxi_min_dbnoise_over_subtraction聽感
MILD-20.00.58-10.01.2最保守,優先保留語音細節
MODERATE-23.00.54-10.01.3mild 與 balanced 之間
BALANCED-25.00.52-10.01.4預設,語音品質與抑噪平衡
AGGRESSIVE-28.00.45-12.01.3抑噪最深,較可能犧牲語音細節
外部可調／內部不開放的完整分類、每個欄位的預設、範圍、耦合與調整方向，見 nr_c_api_params.html。要調增益平滑請改 alpha_decay(必要時連同 alpha_attack);alpha_g 是死旋鈕(會過驗證、會被複製，但 calculate_gain() 從不讀它)。q=0.52 是 balanced 的作者設定,不是把輸出 SPP 固定為 0.52:沒有證據偏向語音或非語音時,Bayesian posterior 自然回到約 q,所以 mean_spp≈0.5 是中性狀態。

為什麼有 retime 系列函式

EMA 係數與 frame 計數多半是在某個參考 hop(10 ms 或 16 ms)下調出來的錨點值;不同 grid 的實際 hop 不同(8／16／10.667 ms),原封套用會讓真實時間常數跑掉。anr_retime_alpha()／_retime_frames()(及帶 _ref／_ms 的顯式版本)把「錨點值 + 錨點 hop」換算成當前 grid 的等效值。

參數越界時它們不報錯:retime_alpha* 原封回傳輸入,retime_frames* 回 0。ref_hop_seconds 刻意用 double——以 float32 表示「16 ms」會讓 ceil() 階梯多跳一格(16k/512 上 L 從 32 變 33)。anr_retime_frames_ms() 的參考 hop 以整數毫秒 ref_hop_ms 給定,ceil(frames × ms × sample_rate ÷ (1000 × hop)) 全程 64-bit 整數運算,預設 config 的 L 用它。

6. 執行期改強度(不重啟、不重配記憶體)

int anr_reconfigure(AnrDenoiser *nr, const AnrConfig *target);
int anr_set_mode(AnrDenoiser *nr, AnrMode mode);
契約內容
幾何必須相同sample_rate／frame_size／hop_size／fft_size／L／num_init_frames 六個欄位必須與 instance 當下值完全相同(這條路徑不重新配置任何記憶體)
刻意保留追蹤中的噪聲底、MCRA 最小值追蹤環與其 run length、SPP 先驗 SNR 歷史、增益平滑歷史全部繼續跑。換強度不是重啟
逐字採用target 不做 preset 查表、不做 overlay 疊加。呼叫端自己疊的覆寫必須自己重建整份,否則會被悄悄還原成 canonical
回 -1self/target 為 NULL、target 未過 validate_config()、六個幾何欄位任一不符。-1 時什麼都沒寫
時序在兩個 frame 之間呼叫、與 process() 序列化。非 thread-safe
set_mode() 與 reconfigure() 不可互換。set_mode() 組的是裸的 canonical preset(L 為函式庫預設),組態等於 canonical preset 的實例可直接用。在 canonical preset 上疊了覆寫的實例,交給 set_mode() 時非 pool 欄位的覆寫會被悄悄還原;覆寫的是 L 或 num_init_frames 時則會因 pool 大小不符而被拒絕。這種實例請自己重組完整組態再呼叫 reconfigure()。
/* 組態等於 canonical preset:直接換 mode */
anr_set_mode(nr, ANR_MODE_AGGRESSIVE);

/* 自己疊了覆寫:重組整份,逐字交出去 */
AnrConfig t = anr_config_for_mode_grid(sr, fft_size, ANR_MODE_AGGRESSIVE);
t.noise_over_subtraction = 1.2f;   /* 範例覆寫,每次都要重新疊上去 */
anr_reconfigure(nr, &t);

anr_reset()

清除 MCRA(噪聲底／最小值追蹤環／ring_idx／scene_change_count)、SPP、增益平滑歷史、init_frame_count。不清除呼叫端自己的 analysis／OLA buffer——library 根本不知道它們存在。self==NULL 時安靜 no-op,沒有任何回報。

reset 後會再次經歷 num_init_frames 個 pass-through frame。換串流／換檔／換裝置／中斷重連時必須呼叫,library 永遠不會自動 reset;而且要同時 reset NR 與 caller 的 WOLA buffer,只做一邊會留下不一致的尾巴。

8. 建置與連結

make -C NR/c_impl lib SIMD=1                  # 產品(ARM NEON)
make -C NR/c_impl lib SIMD=0                  # 純量參考建置
旗標影響
SIMD=0|1手寫核心開關。archive 與消費端 TU 的 SIMD_KERNELS_FORCE_SCALAR 狀態必須一致
-ffp-contract=off必要。任何 include 了 simd_kernels.h／fast_math.h 的你自己的 TU 也要帶

不要混用不同 SIMD 產物;archive 路徑由 build flags hash 決定,用 make -s ... print-lib-path 取得,不要自行拼 bin/ 路徑。不要用 -Ofast／-ffast-math,它們會改變遞迴 DSP 數值。

9. 整合檢查清單

  • grid 是上表五組其中之一,且與鏈上其他 lib 同一組(不要各自取各自的 default)。
  • WOLA 是 periodic sqrt-Hann、50% overlap、frame_size == fft_size、不補零。
  • 每次 process 恰好給 n_freqs 個 bin,函式不會替你檢查長度。
  • pool 基底 16-byte 對齊;get_mem_size() 與 init() 的回傳值都檢查。
  • borrowed pointer(anr_get_gain／anr_get_noise_psd)沒有跨下一次 process() 保存。
  • stream boundary 同時 reset NR 與 caller 的 WOLA/ring state。
  • 要調平滑用 alpha_decay,不是 alpha_g。
  • 沒有 include noise_estimator.h／spp_estimator.h／anr_internal.h；公開／內部函式分級見 參數頁 §6。
