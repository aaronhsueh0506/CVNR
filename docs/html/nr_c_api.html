NR C API 使用說明 — lib/nr/c_impl

本頁是整合者視角的 API 說明：init/process 要呼叫什麼、input/output 怎麼給、每個參數調了會有什麼結果。演算法內部機制見 nr.html;完整欄位與錯誤語意的 canonical 出處是 NR/docs/c_user_manual_zh_TW.md。函式內部自行呼叫的子模組不在本頁範圍。

1. 責任邊界(先看這個)

NR 是純頻域 MMSE-LSA/OMLSA 降噪核心。它只吃 Complex[n_freqs]、只吐 Complex[n_freqs],不含 window、FFT、IFFT、OLA 或任何 PCM buffer 邏輯——這些全部是呼叫端的責任(NR/c_impl/include/mmse_lsa_denoiser.h:2-9,64-68)。

如果 application 手上只有 PCM,不要自己補一套 WOLA。直接用 Audio_ALG 的 pipeline(它已經把 window/FFT/OLA/gain fusion 做對了),或照 串接範例 的做法。

連結時需要兩個 archive:libmmse_lsa.a 與 libaudio_common.a——NR 自己不含 FFT。

與 AEC 的 grid 表不完全相同。AEC 不接受 8k/128(它的 8k legacy grid 是 256/128);NR 的 8 kHz 預設卻是 128/64(mmse_lsa_default_fft_size(),mmse_lsa_types.h:92-96)。串成一條鏈時不要各自呼叫各自的 default,要由上層 resolve 出同一組 (sample_rate, fft_size, hop) 再明確傳給兩邊。

建立後不可中途換 grid:mmse_lsa_reconfigure() 連 grid 都不給換(mmse_lsa_denoiser.c:659-666),要換必須 destroy 重建。

3. 建立與生命週期

兩條路徑永遠同時編進同一份 object(不是 #ifdef 二選一);handle 內有 runtime flag is_static,destroy() 靠它決定要不要真的 free()(mmse_lsa_denoiser.c:104-106,415,463,467-469)。

A. Static pool(板端路徑)

MmseLsaConfig cfg = mmse_lsa_config_for_mode_grid(16000, 256, MMSE_LSA_NR_BALANCED);

if (!mmse_lsa_validate_config(&cfg)) { /* 唯一能事先知道為何被拒的手段 */ }

size_t need = mmse_lsa_get_mem_size(&cfg);   /* 0 = config 無效或尺寸溢位 */
void  *pool = board_alloc_aligned(16, need); /* 基底必須 16-byte 對齊 */
MmseLsaDenoiser *nr = pool ? mmse_lsa_init(pool, need, &cfg) : NULL;
if (!nr) { /* 對齊錯 / pool 太小 / config 無效 */ }

/* ... 每 frame 呼叫 process ... */

mmse_lsa_destroy(nr);   /* static instance 上是真 no-op,可重複呼叫 */
board_free(pool);       /* pool ownership 永遠在 caller */

B. Heap(桌面/測試)

MmseLsaDenoiser *nr = mmse_lsa_create(&cfg);
mmse_lsa_destroy(nr);   /* heap instance 只能呼叫一次,重複呼叫 = double free */

接 AEC 的 r2 時要先換算尺度。AecResContext.r2 是 int16-square scale,直接當 extra_noise_psd 前必須除以 32768²。現有 pipeline 已經處理好,application 不要再複製一份。

stationary 疊加層的陷阱

mmse_lsa_apply_stationary(&cfg)(mmse_lsa_types.h:309-331)是就地疊加,且無 NULL 檢查(傳 NULL 直接當機)。呼叫順序固定:config_for_mode() → apply_stationary() → validate_config()。

它無條件覆寫 g_min_db(→ -30.0)與 xi_min_db(→ -22.0)。所以 mild+stationary／moderate+stationary／aggressive+stationary 的這兩個欄位會變成完全一樣,疊完之後只剩 q 與平滑係數還有差異。若要「mild 的增益下限 + stationary 行為」,必須在 apply_stationary() 之後手動把 g_min_db 改回去,再重跑一次 validate_config()。

為什麼有 retime 系列函式

EMA 係數與 frame 計數多半是在某個參考 hop(10 ms 或 16 ms)下調出來的錨點值;不同 grid 的實際 hop 不同(8／16／10.667 ms),原封套用會讓真實時間常數跑掉。mmse_lsa_retime_alpha()／_retime_frames()(及帶 _ref 的顯式版本)把「錨點值 + 錨點 hop」換算成當前 grid 的等效值。

參數越界時它們不報錯:retime_alpha* 原封回傳輸入,retime_frames* 回 0。ref_hop_seconds 刻意用 double——float32 的「16 ms」曾讓 ceil() 階梯多跳一格(16k/512 上 L 從 32 變 33)。

6. 執行期改強度(不重啟、不重配記憶體)

int mmse_lsa_reconfigure(MmseLsaDenoiser *nr, const MmseLsaConfig *target);
int mmse_lsa_set_mode(MmseLsaDenoiser *nr, MmseLsaNrMode mode);
契約內容
幾何必須相同sample_rate／frame_size／hop_size／fft_size／L／num_init_frames 六個欄位必須與 instance 當下值完全相同(這條路徑不重新配置任何記憶體)
刻意保留追蹤中的噪聲底、MCRA 最小值追蹤環與其 run length、SPP 先驗 SNR 歷史、增益平滑歷史全部繼續跑。換強度不是重啟
逐字採用target 不做 preset 查表、不做 overlay 疊加。呼叫端自己疊的覆寫必須自己重建整份,否則會被悄悄還原成 canonical
回 -1self/target 為 NULL、target 未過 validate_config()、六個幾何欄位任一不符。-1 時什麼都沒寫
時序在兩個 frame 之間呼叫、與 process() 序列化。非 thread-safe
set_mode() 與 reconfigure() 不可互換。set_mode() 組的是裸的 canonical preset,只適用 standalone(它會自動重新套上 stationary overlay,避免變成 hybrid)。兩條出貨 pipeline 的 NR 組態都是「canonical preset 加上自己的覆寫」(broadband_threshold／L／alpha_decay),把 canonical preset 丟給 set_mode() 會因為 L 不同而被拒絕。這正是 audio_pipeline_set_nr_mode()／four_aec_nr_res_set_nr_mode() 各自重組完整組態再呼叫 reconfigure() 的原因——application 不要繞過 pipeline setter。
/* standalone:直接換 mode */
mmse_lsa_set_mode(nr, MMSE_LSA_NR_AGGRESSIVE);

/* 自己疊了覆寫:重組整份,逐字交出去 */
MmseLsaConfig t = mmse_lsa_config_for_mode_grid(sr, fft_size, MMSE_LSA_NR_AGGRESSIVE);
t.broadband_threshold = 0.8f;                        /* 我方覆寫 */
t.L                   = mmse_lsa_retime_frames(150, sr, t.hop_size);
t.alpha_decay         = t.alpha_g;
mmse_lsa_reconfigure(nr, &t);

mmse_lsa_reset()

清除 MCRA(噪聲底／最小值追蹤環／ring_idx／scene_change_count)、SPP、增益平滑歷史、init_frame_count。不清除呼叫端自己的 analysis／OLA buffer——library 根本不知道它們存在。self==NULL 時安靜 no-op,沒有任何回報。

reset 後會再次經歷 num_init_frames 個 pass-through frame。換串流／換檔／換裝置／中斷重連時必須呼叫,library 永遠不會自動 reset;而且要同時 reset NR 與 caller 的 WOLA buffer,只做一邊會留下不一致的尾巴。

SIMD=0|1手寫核心開關。archive 與消費端 TU 的 SIMD_KERNELS_FORCE_SCALAR 狀態必須一致
-ffp-contract=off必要。任何 include 了 simd_kernels.h／fast_math.h 的你自己的 TU 也要帶

不要混用不同 BACKEND／SIMD 產物;archive 路徑由 build flags hash 決定,用 make -s ... print-lib-path 取得,不要自行拼 bin/ 路徑。不要用 -Ofast／-ffast-math,它們會改變遞迴 DSP 數值。

9. 整合檢查清單

  • grid 是上表五組其中之一,且與鏈上其他 lib 同一組(不要各自取各自的 default)。
  • WOLA 是 periodic sqrt-Hann、50% overlap、frame_size == fft_size、不補零。
  • 每次 process 恰好給 n_freqs 個 bin,函式不會替你檢查長度。
  • pool 基底 16-byte 對齊;get_mem_size() 與 init() 的回傳值都檢查。
  • borrowed pointer(_get_gain／_get_spp／_get_noise_psd)沒有跨下一次 process() 保存。
  • stream boundary 同時 reset NR 與 caller 的 WOLA/ring state。
  • 要調平滑用 alpha_decay,不是 alpha_g。
  • 沒有 include mcra_noise_estimator.h／spp_estimator.h。
